# Procedural sky: current 0.1 slice

The Vulkan sky draw combines four artistic palette transforms, a procedural sun/moon, stars and stylised 2D clouds with wind. In the full editor, **Time of day / sky** selects the palette and exposes time, cover, wind, sky-scattering strength, and independent Rayleigh/Mie *artistic weights*. Strength zero skips the LUT samples and returns to the previous palette-only sky. The four palette choices are fixed transforms with live global controls, not four independently editable/saved physical profiles. The compact Android controls do not currently expose the new scattering sliders. HDRI backgrounds bypass this sky shader.

## Transmittance-based approximation

`engine/sky/AtmosphereLut.h` integrates optical depths on the CPU once per process, over a spherical Earth-like planet (radius 6,360 km, atmosphere height 100 km). It uses exponential Rayleigh and Mie density profiles with 8 km and 1.2 km scale heights and a 48-step midpoint integration. RGB stores `exp(-betaRayleigh * depthRayleigh - betaMie * depthMie)`; alpha stores Mie-only transmittance. The coefficients are fixed, in inverse kilometres. Rays intersecting the ground return zero in the underlying math; the texture covers only upward rays. The 256×64 grid maps zenith cosine 0–1 and altitude 0–100 km. It is quantised to linear RGBA8 (64 KiB), uploaded once at renderer initialisation as a clamp/linear sampled texture and reused until renderer destruction. It does not need a network download or runtime LUT render pass.

The sky shader samples view and sun transmittance at a **fixed sea-level virtual observer**, derives approximate Rayleigh and Mie contributions with angular phase functions, and adds the artist-weighted result to the existing gradient in linear HDR before clouds. It fades with night visibility. The palette controls remain separate; scattering strength and weights do **not** change the physical density/extinction coefficients in the LUT. Procedural IBL, surface fog and cloud lighting do not use this scattering, so they need not match the sky. At strength zero the LUT remains allocated but is not sampled by the sky branch.

This is a bounded transmittance-LUT-informed **approximation**, inspired by the transmittance part of modern real-time atmosphere methods. It is not Hillaire's full algorithm: there is no integration of sun transmittance along each view ray, sky-view LUT, multiple scattering, ozone, ground bounce, configurable planet, altitude-aware observer, physically based aerial perspective, or 3D volumetric cloud system. Eight-bit quantisation, the uniform angular grid and filtering can cause banding and horizon error; a fixed sun transmittance can over-darken low-sun scattering. The sun disc and clouds are artistic and do not receive physical transmittance. The separate depth-atmosphere post pass is artistic fog, not this sky model.

## Profiling and verification

On queues supporting timestamps, the editor reports a delayed **GPU sky draw** sample, separately from the post-processing sample. A per-frame query pool is reset in the submitted command buffer and read only after that frame's fence; unsupported queues report unavailable. The sky interval brackets the sky draw inside the main dynamic-rendering pass. It includes timestamp and scheduling effects, can be misleading on tile-based GPUs that defer work, and is not an isolated atmosphere-only cost, frame time or benchmark. Queries themselves can affect performance. Compare with and without scattering, with fixed resolution, cloud settings and camera, and validate on the actual Intel UHD and Android device; emulator timing is not representative.

GPU-free tests cover integration boundaries, extinction ordering, ground occlusion and LUT dimensions/values. Android's emulator integration smoke checks that the real Vulkan sandbox presents and, when supported, obtains both sky and post timestamp samples; it does not validate visual quality or physical-device performance. There is no completed production AnimeSky 1.0 architecture or real-device visual/performance validation yet.
