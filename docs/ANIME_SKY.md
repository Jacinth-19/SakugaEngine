# Procedural sky: current implementation

The Vulkan sky draws four artistic palette styles, a sun/moon, stars and clouds. Each style now has an independently editable slot: scattering strength, Rayleigh/Mie artistic weights, cloud cover, wind, zenith/horizon tint, scattering/cloud mode and atmospheric model parameters. **Save sky profiles** writes all four slots; **Reset profile** resets the selected one. Profile choice itself and time of day are not saved in that file. A corrupt or incompatible file is rejected without changing the in-memory slots. On Windows the file is `%LOCALAPPDATA%/SakugaEngine/sky_profiles.json` when available; on Linux it is `$XDG_CONFIG_HOME/sakuga/sky_profiles.json` or `~/.config/sakuga/sky_profiles.json`; on Android it is the app's `<asset-root>/user/sky_profiles.json`. Fallback paths and save errors are shown in the editor/log. Android also retains unsaved changes during in-process surface recreation, not necessarily after process termination. The `SKY` button opens compact controls including scattering and a collapsible atmosphere model; colour tints are in the full editor.

## Atmosphere

`engine/sky/AtmosphereLut.h` computes a 256×64 linear RGBA8 transmittance LUT on the CPU. RGB contains Rayleigh, Mie and ozone extinction; alpha contains Mie-only transmittance. It integrates 48 midpoint steps in kilometres through a spherical planet with exponential Rayleigh/Mie densities and a triangular ozone layer. The x axis runs from the altitude-dependent geometric horizon to zenith, with a quadratic mapping that concentrates samples near the horizon; ground-occluded rays are rejected. RGBA channels store square-root-encoded transmittance and the shader squares the filtered values, providing more precision for dark transmittance than linear RGBA8. Height is the y axis. Radius, atmosphere height, Rayleigh/Mie scale heights, ozone strength and ground albedo are editable per profile (scattering coefficients and ozone-layer shape remain fixed). Inputs are clamped before use. A model edit rebuilds and uploads the LUT synchronously; in-flight GPU use is waited for and the old image freed. This can cause noticeable stalls while dragging sliders and has not been profiled on target hardware. Albedo does not require LUT regeneration.

The **Integrated scattering** option uses a 65×33 square-root-encoded RGBA8 sky-view LUT. The CPU integrates eight view samples per texel, with 24-step solar transmittance and an approximate ground-bounce term. Its axes are relative solar azimuth and square-root view elevation, with duplicated azimuth endpoints. The sky shader and procedural IBL sample the same table. Sun elevation and observer altitude are quantised (0.05 direction components and 100 metres respectively), as are scattering weights; this limits rebuilds but can produce stepping. Values above 16 are clipped, and the low resolution and encoded-domain filtering can blur the sun-facing lobe or introduce error. The visible artistic gradient, sun, stars and clouds are not reproduced in IBL. HDRI backgrounds bypass the procedural sky.

A 33×16 square-root-encoded RGBA8 **second-scattering LUT** holds a coarse angular mean of first-order atmospheric radiance by altitude and solar zenith. Each texel uses 16 angular directions, eight view samples and 16 solar samples; the later scattering is isotropic. This contribution is integrated into the sky-view bake and sampled by opt-in aerial perspective and volume-cloud ambient lighting. It is a bounded second-order approximation, not Hillaire's multiple-scattering solution or an arbitrary-order transport solver. Its angular quadrature is sparse, its eight-bit storage is approximate, and it does not integrate physical ground reflection, cloud shadows or multiple cloud scattering. The older artistic ground-bounce term is present in the sky-view bake, but not in aerial perspective. The directional sun disc and volume clouds sample atmospheric solar transmittance; the clouds also approximate foreground-air attenuation. These shared inputs improve consistency but do not make clouds, IBL, sky and fog identical.

LUTs are generated on the CPU and uploaded synchronously with the graphics device idle. The transmittance and second-order tables rebuild after optical model edits; the sky-view table rebuilds after quantised sun elevation, altitude, scattering weights or atmospheric-model changes. These updates can stall rendering and produce visible steps; no target-device profiling or visual calibration is claimed. The unchecked integrated-scattering option keeps the lower-cost LUT-informed artistic sky; it does not use the sky-view or second-order LUT. Strength zero disables the added sky scattering and returns to the original, unattenuated artistic sun disc. Integrated scattering defaults on for desktop, but off for Android unless a saved profile enables it. Rayleigh/Mie *artistic weights* scale in-scattering, not extinction.

This is **not the complete Hillaire atmosphere**: its LUT parameterisation, integration and temporal/update architecture differ, there is no complete multiple-scattering solution or physically integrated ground bounce, and aerial perspective remains an approximation over opaque depth only. Artistic gradients, 2D clouds, HDRI backgrounds, surface-fog fallback and transparent objects are not consistently lit by the same atmospheric transport. See [post-processing details](POST_PROCESSING.md).

## Clouds

The default is the existing stylised 2D cloud shader. The opt-in **3D clouds (costly)** mode marches eight samples of procedural 3D density through a flat layer from 1.5 to 3.5 km, limited to 40 km, with wind and transmittance compositing. Each occupied view sample takes three additional density samples towards the sun for approximate cloud self-shadowing and uses the atmospheric transmittance and second-order LUTs for lighting. This is still a basic real 3D density raymarch, not a production volumetric cloud system: the short self-shadow ray is coarse and distance-limited, and there are no cloud shadow maps on scene objects, cloud multiple scattering, temporal reprojection, weather map, adaptive quality, or fully integrated atmosphere/cloud light paths. It is drawn only in the background sky and does not create scene-depth intersections. Mobile defaults to the existing low-cost mode. Neither mode has been visually calibrated or benchmarked on the target devices.

## Profiling and verification

On queues supporting timestamps, the editor reports a delayed GPU **sky draw** sample separately from the post-processing sample. Queries are reset in the submitted command buffer and read after the frame's fence. This is not an atmosphere/cloud breakdown: scheduling and timestamp overhead can affect it, and tile-based GPUs may defer work. It is not a frame benchmark. Compare modes at fixed resolution, time, cloud cover and camera; validate on the actual Intel UHD and Android phone rather than using emulator timing.

GPU-free tests cover optical depth, ground/top intersections, model sanitisation, sky-view LUT seams and reference samples, second-order LUT behaviour, aerial contributions, ozone/bounce response, profile round trips and malformed profiles. Android emulator smoke exercises the renderer and controls but does not establish visual quality, physical accuracy or physical-device performance. This is an incremental implementation, not finished AnimeSky 1.0.
