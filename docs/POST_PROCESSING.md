# AnimeSky post-processing

## Current Vulkan implementation

`engine/post/PostProcessing` owns the descriptor sets, full-screen graphics pipelines and intermediate HDR images independently of the scene renderer. The caller supplies the resolved linear RGBA16F scene and LUT, records the passes on the graphics queue, and receives an RGBA8 display-encoded image. Scene rendering includes sky and clouds, so bright sun, cloud and emissive pixels feed the same prefilter as other bright pixels. ImGui is composited afterwards. This is a scene-wide pipeline, not a baked sky texture.

1. **Optional depth atmosphere:** sample the scene depth, reconstruct radial perspective distance, and blend surface pixels toward the time-of-day fog colour in linear HDR. This pass writes a separate full-resolution HDR image before the bloom chain; clear-depth sky pixels remain unchanged. When enabled it replaces, rather than adds to, the existing toon/outline surface fog.
2. Scene (fogged when enabled) → soft-knee brightness prefilter (half resolution, Karis weighting), followed by the multilevel HDR bloom downsample and additive upsample.
3. **Optional separate halation pass:** wider quarter-resolution diffusion of the bright bloom buffer, composited with a red/orange bias in HDR. It is skipped unless bloom and halation are enabled; the small intermediate remains allocated. This is an artistic approximation, not a physically simulated film emulsion or individually masked lights.
4. HDR bloom/halation composite → exposure → neutral/ACES/clamp tonemap → linear split-tone and saturation → sRGB encoding → display contrast and optional 3D LUT → vignette, grain and display dithering.
5. UI and presentation follow. The scene sky shader has its own gradient, atmosphere approximation and sun/cloud rendering.

The module rebuilds transient images/descriptors on resize or LUT replacement after the caller waits for in-flight frames. It uses dynamic rendering and explicit image barriers on the existing graphics queue, not async compute. Any future pass must document its image format, resolution, layout transitions, lifetime, inputs/outputs and ordering (linear HDR vs display-referred); do not sample an image while writing it. On Android the `Glow` control sets halation when bloom is on. In the full ImGui editor open **Post-processing (HDR)** for four creative presets and individual controls. Presets are independent of the sky palette and preserve exposure, enabled state, and the selected LUT/strength; further slider edits are allowed. Current defaults remain unchanged unless a preset is selected. The Atmospheric preset enables depth atmosphere; use the `Depth atmosphere` checkbox independently. The existing **Lighting / Scene → Fog** control adjusts density. Android also has an `Atmo` toggle in its compact panel.

## Scope and next steps

The four presets are small tunable starting points, not reconstructions of Genshin, Honkai, Wuthering Waves or Wind Waker. They are not yet artist-calibrated on target devices. The threshold is brightness-based: there is no emissive/object selection mask. There is no physically based aerial perspective, physical atmosphere or volumetric clouds, lens flare, chromatic aberration, depth of field, screen-space outline enhancement, colour quantization or painterly filter. Existing geometry outlines, exponential fog, LUT grading, grain, vignette and display dither should not be confused with those missing effects.

Depth atmosphere requires D32 depth to support both sampled and attachment usage at the renderer's selected sample count. Devices without it and nonstandard/reversed/orthographic projections automatically retain the prior per-surface fog. MSAA depth samples are read separately and the fog factors averaged; the already-resolved scene colour is then blended, so silhouette edges are an approximation. Alpha-blended geometry does not write depth and is fogged using the opaque depth behind it (or not fogged against clear sky); it is not correct per-transparent-layer atmospheric scattering. Debug lines likewise follow the opaque depth. The pass preserves clear-depth sky, not true sky/geometry segmentation at the far plane. This is a useful scene-wide approximation, not the complete physical atmosphere architecture.

No GPU timestamp profiling or device-specific performance/visual validation has been added here. Sampleable scene depth is allocated even while the optional atmosphere pass is off on supported devices; the pass also allocates a full-resolution HDR target and stores multisampled depth when enabled. Quarter-resolution halation and the existing bloom chain add GPU bandwidth; test with bloom/halation both off and on, particularly on Intel UHD and phones, before enabling more effects. The Vulkan emulator smoke checks presentation and the mobile control, not image quality or real-hardware timing. CPU tests verify profile values and pass selection without a GPU. Shader sources and their precompiled SPIR-V are both committed.
