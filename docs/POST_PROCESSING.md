# AnimeSky post-processing

## Current Vulkan implementation

`engine/post/PostProcessing` owns the descriptor sets, full-screen graphics pipelines and intermediate HDR images independently of the scene renderer. The caller supplies the resolved linear RGBA16F scene and LUT, records the passes on the graphics queue, and receives an RGBA8 display-encoded image. Scene rendering includes sky and clouds, so bright sun, cloud and emissive pixels feed the same prefilter as other bright pixels. ImGui is composited afterwards. This is a scene-wide pipeline, not a baked sky texture.

1. **Optional depth atmosphere:** sample the scene depth, reconstruct radial perspective distance, and blend surface pixels toward the time-of-day fog colour in linear HDR. This pass writes a separate full-resolution HDR image before the bloom chain; clear-depth sky pixels remain unchanged. When enabled it replaces, rather than adds to, the existing toon/outline surface fog.
2. **Optional depth of field:** a separate full-resolution, nine-tap HDR gather, using scene depth to set a circle-of-confusion radius around the user-selected focus distance/range. The pass accepts either the original or the fogged scene and precedes bloom. It is off by default.
3. Scene → soft-knee brightness prefilter with optional per-material and warm/cool/saturated colour-key selection (half resolution, Karis weighting), followed by the multilevel HDR bloom downsample and additive upsample. When supported, the main scene pass writes a separate R8 material-weight attachment, resolved with MSAA; the prefilter samples this mask alongside HDR colour. Sky has an independent mask weight.
4. **Optional separate halation pass:** wider quarter-resolution diffusion of the bright bloom buffer, composited with a red/orange bias in HDR. It is skipped unless bloom and halation are enabled; the small intermediate remains allocated. This is an artistic approximation, not a physically simulated film emulsion or individually masked lights.
5. HDR bloom/halation and optional stylised bloom-derived lens ghosts → exposure → neutral/ACES/clamp tonemap → linear split-tone and saturation → sRGB encoding → display contrast and optional 3D LUT → vignette, grain and display dithering.
6. **Optional display-space finishing pass:** adjustable chromatic channel offset, luma edge darkening, edge-preserving smoothing and colour quantisation with a small ordered dither. It writes a separate target and is skipped when all controls are off.
7. UI and presentation follow. The scene sky shader has its own gradient, atmosphere approximation and sun/cloud rendering.

The module rebuilds transient images/descriptors on resize or LUT replacement after the caller waits for in-flight frames. It uses dynamic rendering and explicit image barriers on the existing graphics queue, not async compute. Any future pass must document its image format, resolution, layout transitions, lifetime, inputs/outputs and ordering (linear HDR vs display-referred); do not sample an image while writing it. On Android the `Glow` control sets halation when bloom is on. In the full ImGui editor open **Post-processing (HDR)** for four creative presets and individual controls. Presets are independent of the sky palette and preserve exposure, enabled state, and the selected LUT/strength; further slider edits are allowed. Current defaults remain unchanged unless a preset is selected. The Atmospheric preset enables depth atmosphere; use the `Depth atmosphere` checkbox independently. The existing **Lighting / Scene → Fog** control adjusts density. Android also has an `Atmo` toggle in its compact panel. Its `FX` button toggles a small combination of lens ghosts, chromatic aberration, ink edges and material bloom masking where supported, plus depth of field where depth sampling is supported. The full editor exposes the individual controls.

## Scope and next steps

The four presets are small tunable starting points, not reconstructions of Genshin, Honkai, Wuthering Waves or Wind Waker. They are not yet artist-calibrated on target devices. Enable **Per-material bloom mask** and edit `bloomWeight` and `bloomEmissionOnly` under the material inspector's **Rim / Emission / Highlight** group. Weight 0 excludes that material; weight 1 permits normal thresholded bloom. Emission-only blends toward a gate calculated from the emission texture, colour and strength; it is not an extraction of only emitted radiance. Sky/cloud weights are controlled separately. Materials shared by objects share the same weight. When the R8 attachment/resolve/filter/blend capabilities are unavailable, the mask is disabled and ordinary colour-key bloom remains. Transparent mask coverage is alpha blended; outlines inherit their material weight (the emission-only part is suppressed), and debug lines write zero weight. The mask represents the original scene before optional depth-of-field blur, so boundary halos can be approximate. The R8 mask attachment is allocated and written on supported devices even when the option is off; it adds bandwidth and MSAA memory cost. There is no physically based aerial perspective, physical atmosphere or volumetric clouds. The lens flare is an artistic bloom-derived ghost, not an occluded sun-specific or physically simulated lens. The screen ink is a colour-luminance edge filter, not depth/normal silhouette reconstruction; painterly finishing is simple edge-aware smoothing, not brush-stroke synthesis.

Depth atmosphere requires D32 depth to support both sampled and attachment usage at the renderer's selected sample count. Devices without it and nonstandard/reversed/orthographic projections automatically retain the prior per-surface fog. MSAA depth samples are read separately and the fog factors averaged; the already-resolved scene colour is then blended, so silhouette edges are an approximation. Alpha-blended geometry does not write depth and is fogged using the opaque depth behind it (or not fogged against clear sky); it is not correct per-transparent-layer atmospheric scattering. Debug lines likewise follow the opaque depth. The pass preserves clear-depth sky, not true sky/geometry segmentation at the far plane. This is a useful scene-wide approximation, not the complete physical atmosphere architecture.

A Vulkan timestamp query measures the whole post-processing section on the graphics queue; it is displayed as a delayed GPU post time in the full editor when the queue supports timestamps. It is not a per-pass breakdown, frame benchmark, or display measurement, and it does not wait for the GPU on the current frame. No device-specific performance or visual validation has been done. Sampleable scene depth is allocated even while depth effects are off on supported devices; atmosphere and depth of field each allocate a full-resolution HDR target, and a full-resolution RGBA8 target is allocated for the finishing pass. Multisampled depth is stored when needed. Depth of field uses nearest opaque depth at MSAA edges, lacks foreground/background occlusion-aware gathering, and inherits the same transparent-depth limitations as fog. It is not physically exact. Quarter-resolution halation and the existing bloom chain add GPU bandwidth; test with bloom/halation both off and on, particularly on Intel UHD and phones, before enabling more effects. The Vulkan emulator smoke checks presentation and the mobile control, not image quality or real-hardware timing. CPU tests verify profile values and pass selection without a GPU. Shader sources and their precompiled SPIR-V are both committed.
